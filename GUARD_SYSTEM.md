# Система Guard кодов с ограничениями

FunPay Cardinal включает усовершенствованную систему Guard кодов для оффлайн активации с защитой от злоупотреблений. Система поддерживает два метода получения кодов: **Shared Secret** (рекомендуется) и **Gmail** (как резервный).

## 🎯 Особенности системы

### Основные функции
- **Автоматическая проверка покупок** - Guard коды доступны только покупателям
- **Ограничение попыток** - 3 попытки запроса кода на покупку
- **Время действия кода** - 30 секунд для оффлайн активации
- **Два метода получения кодов**:
  - **Shared Secret** (рекомендуется) - мгновенная локальная генерация
  - **Gmail** (резервный) - получение из писем
- **Отслеживание попыток** - отображение оставшихся попыток пользователю
- **Универсальность** - работает для Steam, Epic Games, Origin, Uplay и других платформ

### Архитектура системы

```
guard_command_handler.py  →  Обработка команды !code
         ↓
purchase_checker.py        →  Проверка покупки и попыток
         ↓
guard_handler.py           →  Управление Guard системами
         ↓
shared_secret_guard.py    →  Получение кодов (основной метод)
         ↓
gmail_guard_integration.py →  Получение кодов (резервный метод)
```

## 🔧 Компоненты системы

### 1. purchase_checker.py
Отвечает за проверку покупок и ограничение попыток.

**Основные функции:**
- `add_purchase()` - регистрация покупки
- `can_request_code()` - проверка возможности запроса кода
- `record_code_attempt()` - регистрация попытки запроса
- `get_remaining_attempts()` - получение оставшихся попыток
- `reset_attempts()` - сброс попыток

**Настройки:**
- `max_attempts = 3` - максимальное количество попыток
- `verification_window = 3600` - время верификации покупки (1 час)

### 2. guard_command_handler.py
Обрабатывает команду `!code` и интегрирует все компоненты.

**Функционал:**
- Перехватывает команду `!code`
- Проверяет покупку через `purchase_checker`
- Проверяет лимит попыток
- Получает Guard код через Guard систему (автоматически выбирает метод)
- Отправляет код с информацией о попытках

### 3. guard_handler.py
Управляет Guard системами (поддерживает оба метода).

**Основные функции:**
- `init_gmail()` - инициализация Gmail подключения
- `init_shared_secret()` - инициализация shared_secret менеджера
- `add_shared_secret_account()` - добавление аккаунта с shared_secret
- `get_guard_code()` - получение Guard кода (автоматически выбирает метод)

**Приоритет методов:**
1. Shared Secret (если доступен)
2. Gmail (как fallback)
3. Конфиг автоответов (если ни один метод не доступен)

### 4. shared_secret_guard.py
Локальная генерация Guard кодов через shared_secret.

**Основные функции:**
- `SharedSecretGuard` - класс для генерации кодов
- `SharedSecretManager` - менеджер для нескольких аккаунтов
- `generate_code()` - генерация кода для указанного времени
- `get_code_with_time_remaining()` - получение кода с информацией о времени

**Преимущества:**
- Мгновенная генерация (миллисекунды)
- Не требует Gmail
- Работает локально
- Поддерживает все платформы

### 5. gmail_guard_integration.py
Получение Guard кодов из Gmail (резервный метод).

### 3. guard_handler.py
Управляет Gmail интеграцией.

**Основные функции:**
- `init_gmail()` - инициализация Gmail подключения
- `get_guard_code()` - получение Guard кода

### 4. gmail_guard_integration.py
Работает с Gmail для получения Guard кодов.

**Настройки:**
- Проверка писем каждые 15 секунд
- Время действия кода: 45 секунд
- Автоматическая очистка истекших кодов

## 🚀 Настройка системы

### 1. Настройка Gmail

Для работы системы необходим Gmail аккаунт:

1. Включите 2FA на Gmail
2. Создайте пароль приложения:
   - Перейдите в Google Account → Security
   - Выберите "2-Step Verification" → "App passwords"
   - Создайте пароль для "Mail"
3. Настройте интеграцию в коде или через конфиг

### 2. Интеграция с ботом

Система автоматически интегрируется через плагины:


## 📋 Процесс работы системы

### Для покупателя:

1. **Покупка товара**
   - Покупатель оформляет заказ на FunPay
   - Бот автоматически выдает товар
   - Покупка регистрируется в системе

2. **Запрос Guard кода**
   - Покупатель отправляет команду `!code`
   - Система проверяет покупку
   - Система проверяет количество попыток
   - При успехе - выдается Guard код

3. **Использование кода**
   - Код действителен 30-45 секунд
   - Покупатель вводит код в Steam
   - При ошибке можно попробовать снова (если есть попытки)

### Для администратора:

1. **Мониторинг**
   - Логи всех запросов кодов
   - Отслеживание попыток
   - Статистика покупок

2. **Управление**
   - Сброс попыток для пользователей
   - Проверка логов
   - Настройка параметров

## 🔒 Безопасность

### Защита от злоупотреблений

1. **Проверка покупки**
   - Код выдается только после подтвержденной покупки
   - Время верификации: 1 час

2. **Ограничение попыток**
   - Максимум 3 попытки на покупку
   - Предотвращает перебор кодов

3. **Время действия кода**
   - Код действителен 30-45 секунд
   - Минимизирует возможность повторного использования

4. **Логирование**
   - Все действия записываются в логи
   - Удобно для анализа проблем

## 🛠️ Устранение проблем

### Проблема: Код не выдается

**Возможные причины:**
1. Покупка не зарегистрирована
2. Истекло время верификации (1 час)
3. Превышен лимит попыток

**Решения:**
- Проверьте логи бота
- Убедитесь, что покупка прошла успешно
- При необходимости сбросьте попытки через поддержку

### Проблема: Gmail не получает письма

**Возможные причины:**
1. Неверные данные Gmail
2. Пароль приложения не создан
3. Steam не отправляет письма на этот email

**Решения:**
- Проверьте правильность email и пароля
- Создайте пароль приложения
- Убедитесь, что Steam использует этот email

### Проблема: Код истекает слишком быстро

**Решения:**
- Увеличьте время в `gmail_guard_integration.py`
- Уменьшите интервал проверки Gmail
- Проверьте синхронизацию времени
