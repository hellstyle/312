# Система форм заказов Amazing RP

FunPay Cardinal включает усовершенствованную систему форм заказов для Amazing RP с автоматической проверкой и валидацией.

## 🎯 Особенности системы

### Основные функции
- **Автоматический парсинг форм** - распознавание заполненных форм в сообщениях
- **Валидация данных** - проверка всех обязательных полей
- **Проверка перед заказом** - автоматическая проверка наличия формы при заказе
- **FAQ система** - автоматические ответы на часто задаваемые вопросы
- **Интеграция с Guard** - совместимость с системой Guard кодов

### Ключевые особенности Amazing RP
- **Навыки дальнобоя идут за 1 единицу уровня** (не за 10!)
- **Обязательная форма** с 4 вопросами перед заказом
- **Согласие с рисками** - понимание возможности наказания от сервера
- **Согласие с правилами FunPay** - возврат 50% при частичном выполнении

## 🔧 Компоненты системы

### 1. form_processor.py
Отвечает за парсинг и валидацию форм.

**Основные функции:**
- `parse_form()` - распознавание формы в сообщении
- `validate_form()` - проверка данных формы
- `submit_form()` - сохранение заполненной формы
- `check_form_submitted()` - проверка наличия формы
- `get_form_summary()` - генерация описания формы

### 2. form_command_handler.py
Обрабатывает сообщения с формами в реальном времени.

**Функционал:**
- Автоматическое распознавание форм в чате
- Валидация данных при получении
- Сохранение форм в системе
- Отправка подтверждения пользователю

### 3. handlers.py (интеграция)
Проверяет наличие формы перед обработкой заказа.

**Функционал:**
- Автоматическая проверка при заказе Amazing RP
- Блокировка заказов без формы
- Отправка уведомлений о необходимости заполнения

## 📋 Форма заказа

### Обязательные вопросы:

1. **Сервер** - название сервера Amazing RP
2. **Уровни** - с какого по какой уровень прокачка
3. **Согласие с рисками** - ДА/НЕТ (возможность наказания от сервера)
4. **Согласие с правилами FunPay** - ДА/НЕТ (возврат 50% при частичном выполнении)

### Пример заполнения:

```
Сервер: Emerald
Уровни: с 1 по 10
Согласие с рисками: ДА
Согласие с правилами FunPay: ДА
```

## 🚀 Использование системы

### Для покупателя:

1. **Изучение FAQ**
   ```
   !faq
   ```
   Получает информацию о системе подсчета навыков (1 единица уровня)

2. **Получение формы**
   ```
   !form
   ```
   Получает инструкцию по заполнению формы

3. **Заполнение формы**
   ```
   Сервер: Emerald
   Уровни: с 1 по 10
   Согласие с рисками: ДА
   Согласие с правилами FunPay: ДА
   ```
   Система автоматически распознает и валидирует форму

4. **Оформление заказа**
   - После подтверждения формы покупатель оформляет заказ на FunPay
   - Указывает данные из формы в описании заказа

### Для продавца:

1. **Настройка шаблона**
   ```bash
   python apply_template.py amazing_rp
   ```

2. **Обновление цен**
   - Редактируйте команду `!price` в `configs/auto_response.cfg`
   - Укажите актуальные цены на прокачку

3. **Мониторинг заказов**
   - Система автоматически проверяет формы
   - При отсутствии формы отправляется уведомление
   - Логи всех действий записываются

## 🔒 Валидация форм

### Проверяемые параметры:

1. **Согласие с рисками**
   - Должно быть "ДА" или "YES"
   - Обязательно для понимания рисков

2. **Согласие с правилами FunPay**
   - Должно быть "ДА" или "YES"
   - Обязательно для согласия с правилами площадки

3. **Уровни**
   - Начальный уровень должен быть меньше конечного
   - Максимальный диапазон: 100 уровней
   - Только числовые значения

4. **Сервер**
   - Минимум 2 символа
   - Не может быть пустым

### Сообщения об ошибках:

- ❌ Необходимо согласие с возможностью наказания (ДА)
- ❌ Необходимо согласие с правилами FunPay (ДА)
- ❌ Начальный уровень должен быть меньше конечного
- ❌ Слишком большой диапазон уровней (максимум 100)
- ❌ Некорректное название сервера

## 🛠️ Устранение проблем

### Проблема: Форма не распознается

**Возможные причины:**
1. Неверный формат полей
2. Отсутствие обязательных полей
3. Некорректные значения

**Решения:**
- Проверьте формат по образцу из команды `!form`
- Убедитесь, что все 4 поля заполнены
- Используйте точные названия полей

### Проблема: Заказ отклонен без формы

**Решения:**
- Покупатель должен сначала заполнить форму
- Отправить команду `!form` для получения инструкции
- Заполнить форму в чате
- После подтверждения оформить заказ заново

### Проблема: Покупатель не понимает систему подсчета

**Решения:**
- Отправьте команду `!faq`
- Лично объясните: "1 единица уровня = 1 уровень навыка"
- Приведите пример: "с 1 по 10 = 10 единиц = 10 уровней"
- Попросите подтвердить понимание
